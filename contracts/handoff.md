# Handoff contract

Give the next worker the objective, authorised scope, acceptance criteria,
relevant sources, validation requirements, and material stop conditions. Include
decisions and assumptions only when they affect the work. A bounded request and
relevant files can provide this context without a separate planning document.

Lead results with the outcome or verdict. Include evidence for required checks,
material decisions or risks, blockers, and any remaining action. Link files or
artifacts when they help the reader inspect or act. Fixed headings, empty
categories, and exhaustive file inventories are unnecessary unless the project
or an actual consumer requires them.

Update planning, progress, or review artifacts when the project requires them or
the chosen formal workflow uses them. Do not create them for otherwise complete
bounded work. Keep the chat handoff proportional and do not repeat full artifact
contents or test logs.

Apply the autonomy, collaboration, completion, model-routing, and state
contracts from this directory where relevant. Project adapters add local
validation and source-of-truth requirements.

`bwh-ask` is exempt from this contract: it produces no artifact and no
workflow handoff.
